# Filesystem boundary handoff to #48 and #51

Ticket #89 adds one neutral `FilesystemBoundary` value to RuntimeBackend allocation and observation evidence. It does not add a file API, host mount input, or provider type.

| Contract value | Meaning |
| --- | --- |
| `WorkingDirectory` | Backend-selected path visible inside the worker; never a caller-selected host path. |
| `OutsideBoundary` | `RuntimeReadOnlyOtherUnavailable`: runtime files may be read-only; other task data outside the directory is unavailable. |
| `Ephemeral` | Cleanup releases the task directory with no supported workspace retention. |
| `EvidenceLevel` | `Simulated`, `BackendVerified`, or explicit `Unsupported`. |

The in-memory reference reports `/workspace`, the fixed outside rule, ephemeral cleanup, and `Simulated`. Its model cases cover task read/write, traversal/outside denial, fresh replacement, and post-termination/cleanup denial. A separate trusted local fixture runs real git and Go commands and exports a bounded regular file before deleting its workspace; that proves compatibility only.

The current Agent Sandbox adapter reports `Unsupported`. Ticket #48 must map the worker-visible directory, writable/read-only mount layout, HOME/temp/cache placement, and unsupported gaps without changing the shared shape. Ticket #51 must then provide real worker evidence for ordinary commands, outside and alias denial, cross-claim freshness, absence of host credentials/mounts, and cleanup. Only that evidence may promote the adapter to `BackendVerified`.
